# QRBuddy launch remediation — 13 October 2026

## Release decision

**Free product: release the reviewed fixes. Paid launch: keep checkout closed
until a real purchase and recovery check pass.** The implemented offer is one
Supporter Pass: **A$49 AUD, 365 days, no automatic renewal**. The existing
Square merchant is active and accepts AUD. No purchase was made during this
work.

This record supersedes the starting-state findings in the
[launch audit](./LAUNCH-READINESS-2026-10-13.md), which also maps the
architecture, main files, flows, and longer-term suggestions.

## Requirements before taking payments

1. Verify a real A$49 checkout, Square receipt, webhook fulfillment and browser
   pass activation. Confirm the merchant/customer-facing name and receipt.
2. Exercise delayed/duplicate webhook, cancelled/declined checkout and closing
   the return tab. Restore the purchased pass in a second browser from its saved
   copy; verify its expiry and paid upload admission.
3. Confirm `pablo@qrbuddy.app` actually receives support/refund mail. DNS or an
   email link is not evidence of mailbox delivery. Do a receipt-based support
   recovery and refund drill using the purchased order.
4. Leave `SQUARE_CHECKOUT_ENABLED=false` until those checks pass. After
   enabling, confirm the availability endpoint and modal show the purchasable
   offer. See [payment operations](./ETHICAL_PAYMENT_SETUP.md).

Refunds currently do not revoke an already-issued signed pass. This is
disclosed; if refunds must revoke access, add a pass identity/revocation
mechanism before making that promise. A repeat purchase issues a fresh 365-day
pass; it does not extend an existing pass's remaining time.

## Remaining validation and useful next work

- Physical iPhone/Safari and Android camera scanning, downloads, clipboard,
  in-app browsers and printed gradient/logo codes. Chromium viewport tests do
  not establish these results.
- Exercise interrupted large uploads, abandoned grants, repeated finalization
  and storage cleanup at realistic sizes before promoting bulk 500 MB sharing.
  Exact-size signing prevents oversized PUTs, but admission ceilings are not a
  hard total storage/billing cap. Set provider spending and storage alerts.
- Monitor daily cleanup and payment webhook failures; keep a small operator
  checklist for receipts, lost passes and expired/failed shares.
- Investigate automated crawler 403 responses before an SEO campaign. Finish
  remaining Spanish islands, tune sample/print guidance and collect actual
  customer evidence before claims about adoption or conversion.
- A true guest wedding album needs multi-guest collection, permissions, quotas,
  organizer export and a retention contract. The current single-slot locker is
  not that product.
- Disable the unused Cloudflare Insights script injection at the provider if
  desired; it is currently blocked by the app's strict CSP. The configured Umami
  and QRBuddy beacon sources are allowed. No CSP relaxation was needed.
- Supabase's `pg_net` extension-in-public advisory remains a maintenance item;
  moving an extension used by scheduled cleanup needs a separate migration and
  scheduler validation.

No framework rewrite, account system, extra pricing tiers, or automated refund
revocation is required to make this first supported offer coherent.
